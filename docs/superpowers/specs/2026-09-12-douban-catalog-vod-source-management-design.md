# 豆瓣影视目录与可管理播放源设计

## 1. 目标

将 TV、移动端和网页版影视界面的片单、筛选条件与影片元数据统一改为设备端从豆瓣刮削；好好看及现有八个 MacCMS 站点只承担影片匹配、剧集信息和播放地址解析。后台增加影视源草稿管理、手动推送、单源指定影片测速及弹窗试看。播放器根据清晰度、起播延迟和近期成功率自动选择最佳线路，并在失败时无感切换下一条线路。

## 2. 已确认的产品规则

- 豆瓣是影视片单和影片信息的唯一来源。
- 每台设备的 Android 内置 Python 后端直接访问豆瓣和各播放源；不建立云端集中式豆瓣目录服务。
- 现有公网云服务继续承担热更新和影视源配置分发。
- 首页与片库保留五个产品类别：电影、电视剧、动漫、综艺、短剧。
- 首页每类固定展示“最近热门、最新上映、豆瓣高分”。
- 片库筛选使用“类别、类型、地区、年份、评分、排序”；删除语言筛选。
- 片库排序为“热门、最新上映、豆瓣高分”。
- 豆瓣片单中没有匹配播放源的影片仍保留展示，详情页显示“暂无片源”。
- 后台支持影视源新增、编辑名称和网址、删除、启停、测速、指定影片测试和弹窗试看。
- 后台编辑只产生草稿；管理员点击“立即推送”后才生成线上配置版本并通知 App 拉取。
- 本次为好好看和现有八个 MacCMS 来源提供适配器。新增网址优先自动识别 MacCMS JSON/XML；不兼容格式明确报错，不静默保存成可用源。
- 测试结果使用“优秀、良好、一般、不可用”四级结论，并显示一句简短说明，不在默认界面堆叠技术明细。

## 3. 总体架构

### 3.1 设备端数据链路

1. App 内置后端启动时载入最近一次有效的豆瓣缓存和随包内置的豆瓣兜底快照。
2. 后端按需请求豆瓣公开页面或公开 JSON 响应，生成统一目录、分类筛选和影片详情。
3. 新鲜结果写入设备本地磁盘缓存；豆瓣请求失败时返回最近一次有效缓存，再回退到随包快照。
4. 用户打开详情或点击播放后，后端使用豆瓣标题、原名、别名、年份、类别和季度并行搜索全部启用的播放源。
5. 匹配结果经过置信度判断，低置信度结果不得自动播放。
6. 可用线路执行播放清单探活、分辨率检测和延迟测量，生成设备本地排名。
7. 播放器选择第一名；起播超时或播放失败时顺序尝试下一名，用户仍可在“换源线路”中手动选择。

### 3.2 公网配置链路

1. 管理员在现有后台新增、编辑、删除或启停影视源，变更写入草稿配置。
2. 后台顶部显示“立即推送”按钮、未发布变更数量、线上版本和最后推送时间。
3. 点击“立即推送”后，服务端校验全部启用源，生成不可变的递增版本配置。
4. App 按现有公网更新机制定时检查影视源配置版本；发现新版后下载、校验并原子替换本地配置。
5. 下载、格式校验或完整性校验失败时继续使用旧版配置。
6. 首次安装或公网不可用时使用 APK/热更新包内置的默认源配置。

云端不保存或汇总豆瓣片单、用户播放记录、设备测速结果；设备测速结果只保存在设备本地。云端仅保存影视源草稿与已发布版本。

## 4. 模块边界

### 4.1 `douban_catalog`

负责豆瓣目录、榜单、筛选、搜索和详情解析，不依赖播放源模块。输出统一的 `DoubanSubject`：

- `douban_id`
- `title`
- `original_title`
- `aliases`
- `year`
- `media_category`
- `genres`
- `regions`
- `season`
- `rating`
- `rating_count`
- `summary`
- `directors`
- `actors`
- `poster_url`
- `backdrop_url`
- `release_date`

豆瓣页面结构变化或限流只影响本模块；消费者始终读取稳定的统一模型。

### 4.2 `douban_cache`

使用内存缓存加设备磁盘缓存：目录和榜单成功结果缓存 6 小时，筛选元数据缓存 24 小时，详情缓存 7 天，搜索缓存 30 分钟。失败响应不覆盖最近一次成功数据。磁盘缓存带 schema 版本、抓取时间和来源 URL，超过期限仍可作为 stale 容灾数据返回。

### 4.3 `vod_source_registry`

负责加载内置默认源、拉取线上已发布配置、校验版本并原子替换。每个源包含：

- `id`：发布后稳定不变的 UUID
- `name`
- `site_url`
- `api_url`
- `adapter_type`：`hhkan`、`macms_json` 或 `macms_xml`
- `enabled`
- `revision`

删除操作在草稿中移除该源；已发布配置仍保持不可变，可由后台历史版本恢复。客户端不得使用草稿配置。

### 4.4 `vod_source_adapters`

统一接口包含：

- `discover(site_url)`：识别首页或采集接口，返回适配器类型和规范化 API 地址。
- `search(subject)`：返回候选影片。
- `detail(candidate)`：返回线路及剧集。
- `resolve(line, episode)`：返回最终播放地址。
- `probe(stream_url)`：返回存活状态、分辨率和延迟。

好好看使用专用适配器；暴风、极速、金鹰、虎牙、豪华、红牛、速播、360 使用 MacCMS 适配器和各自默认地址。后台输入普通站点首页时依次探测当前站点公开声明、常见 MacCMS JSON 路径和 XML 路径；仅在完成搜索与详情验证后允许保存为可用源。

### 4.5 `vod_matcher`

匹配置信度满分 100：

- 标题、原名或别名规范化后完全一致：60 分。
- 年份一致：20 分；相差一年：10 分。
- 电影/剧集/动漫/综艺/短剧类型一致：10 分。
- 季度一致或双方均无季度：10 分。

自动播放阈值为 80 分。60–79 分只作为诊断候选，不进入自动线路；低于 60 分丢弃。同名且年份不同的影片不得仅凭标题自动匹配。

### 4.6 `vod_ranker`

线路综合分满分 100：

- 清晰度 50%：2160p=100、1080p=85、720p=65、低于 720p=35、未知=20。
- 起播延迟 30%：不超过 1 秒=100、1–3 秒=80、3–6 秒=50、超过 6 秒=20、超时=0。
- 近期成功率 20%：取设备本地最近 20 次解析和起播结果；无历史记录使用 50。

不可解析、非 HTTP(S)、播放清单无有效媒体段或探测明确失败的线路标记不可用并沉底。综合分相同则依次按更高分辨率、更低延迟、源配置顺序排序。详情匹配和线路排名缓存 10 分钟。

## 5. 豆瓣目录映射

### 5.1 五类导航

- 电影：豆瓣电影条目。
- 电视剧：豆瓣剧集条目。
- 动漫：电影或剧集中类型包含“动画”的条目。
- 综艺：剧集中类型包含“综艺”或“真人秀”的条目。
- 短剧：标签或类型明确包含“短剧、微短剧、网络短剧”的条目；普通动画短片、纪录短片和剧情短片不得仅因“短片”标签进入短剧。

### 5.2 首页三栏目

- 最近热门：使用豆瓣热门排序和近期口碑信号。
- 最新上映：按电影上映日期或剧集首播日期倒序。
- 豆瓣高分：按评分排序，并以评价人数作为同分稳定排序条件，避免少量评价条目占据前列。

### 5.3 片库筛选

- 类别：电影、电视剧、动漫、综艺、短剧。
- 类型：从当前类别的豆瓣类型集合生成。
- 地区：使用制片国家/地区并做“中国大陆、中国香港、中国台湾”等规范化。
- 年份：使用上映或首播年份，保留“更早”。
- 评分：全部、9 分以上、8 分以上、7 分以上、暂无评分。
- 排序：热门、最新上映、豆瓣高分。

现有 TV/移动端胶囊筛选和网页响应式筛选布局保留，只替换数据来源、筛选项和文案。TV 遥控焦点顺序保持从上到下逐行移动；移动端允许自然换行；不得照搬豆瓣桌面网页布局。

## 6. 后台影视源管理

### 6.1 列表与编辑

后台新增“影视源”页面，显示名称、站点地址、适配器、启用状态、最近测速结论、草稿状态和操作。每行提供“编辑、测试、删除”；页面顶部提供“新增影视源、立即推送”。

新增或编辑时输入名称和网站/API 地址。系统自动发现适配器并执行最小验证。验证失败时允许保留表单内容，但不得把该条目标记为启用。删除前显示确认对话框；删除只修改草稿。

### 6.2 草稿与推送

任何增删改或启停产生未发布状态。“立即推送”在没有变更时禁用；有变更时显示数量。点击后先执行 schema、URL 安全和至少一个启用源检查，再发布递增版本。发布成功后显示版本号和时间；失败时草稿保留，线上版本不变。

### 6.3 指定影片测试与试看

每个影视源的“测试”按钮打开弹窗：

1. 管理员输入影片名称，可选年份和集数。
2. 后台只调用当前源，执行搜索、详情、选集、解析和播放清单探测。
3. 返回“优秀、良好、一般、不可用”及一句结论，例如“1080P，起播较快”。
4. 找到可播放线路时启用“试看”按钮，在同一弹窗内播放。
5. 试看播放器显示加载、播放、失败和结束状态；关闭弹窗立即停止请求与媒体播放。

分级规则：综合分不低于 80 为优秀，60–79 为良好，40–59 为一般，低于 40 或无法播放为不可用。后台测试结果代表后台当前网络环境，不写入 App 的设备本地成功率，也不自动修改源配置或发布草稿。

## 7. 客户端行为

- TV、移动端和网页版使用相同接口模型和文案。
- 目录卡片 ID 改为 `douban:{douban_id}`，收藏、历史和返回焦点使用该稳定 ID。
- 旧 `hhkan:*` 收藏和历史在首次遇到时通过标题与年份迁移到豆瓣 ID；无法可靠匹配时保留旧记录，不删除用户数据。
- 详情首先展示豆瓣信息；播放源匹配异步完成后更新播放按钮状态。
- 没有可用源时，播放按钮替换为不可操作的“暂无片源”，但收藏和详情浏览保持可用。
- 匹配过程中显示“正在查找片源”，不把暂时未完成误报为“暂无片源”。
- 自动换源时显示短暂提示“当前线路不可用，正在切换”，不退出播放器。

## 8. 错误处理与安全

- 豆瓣请求实行请求合并、指数退避和并发上限，避免逐卡请求导致限流。
- 所有外部地址只允许 HTTP(S)；生产配置默认要求 HTTPS。
- 新增源执行 DNS 公网地址校验，拒绝环回、私网、链路本地、保留地址和重定向到这些地址，防止 SSRF。
- 已发布配置包含 schema、版本、生成时间和 SHA-256；客户端下载到临时文件，完整验证后再替换正式文件。
- 任何单个来源失败不得让豆瓣目录、其他播放源或后台列表整体失败。
- 豆瓣解析失败时保留最近一次有效缓存并标注 stale；没有缓存时使用随包快照。
- 播放地址只在当前播放会话内使用，不写入云端配置。

## 9. 发布与兼容

- Python 后端新增模块必须加入 Android 内置后端、移动端同步目录、云端网页版构建包和热更新必需文件清单。
- `tools/sync_shared.py` 继续保证 TV 与移动端共享数据/播放代码一致。
- 首个版本内置当前九个影视源配置，避免客户端尚未拉到线上配置时无源可用。
- 现有 `/hhkan/*` 接口保留一个兼容周期，客户端新代码切换到统一 `/vod/*` 接口；兼容层内部转发到新模块，不再生成界面片单。
- 配置发布与 APK/后端热更新相互独立：只改源无需发布 APK；新增适配器代码仍需热更新。

## 10. 测试与验收

### 10.1 自动化测试

- 豆瓣首页、分类、筛选、搜索和详情解析使用固定 HTML/JSON fixture 做契约测试。
- 缓存测试覆盖新鲜命中、过期 stale、失败不覆盖成功数据和内置快照回退。
- 匹配测试覆盖别名、标点差异、同名不同年份、季度差异和阈值边界。
- 排名测试覆盖不同清晰度、延迟、成功率、死线沉底和稳定的并列排序。
- 源发现测试覆盖 MacCMS JSON、MacCMS XML、好好看、非兼容网站及 SSRF 地址。
- 配置发布测试覆盖草稿隔离、递增版本、失败不替换、客户端原子更新和旧版回退。
- 后台测试接口覆盖匹配不到、解析失败、可播放和四级结论。
- Android JVM/UI 测试覆盖 `douban:*` ID、筛选项、暂无片源、加载状态和自动换源。

### 10.2 集成验收

- 使用豆瓣当前电影、剧集、动漫、综艺和短剧样本验证五类目录及三栏目。
- 使用当前九个源对指定影片执行匹配，核对年份和类型，防止串片。
- 在后台完成新增、编辑、删除、启停、测试、试看、立即推送全流程。
- 在 TV、移动端和网页版验证新配置到达且旧配置在失败时仍可用。
- 使用可控慢源和坏源验证最佳线路排序、起播失败自动换源和手动换源。
- Android 端在 TV 遥控、手机竖屏和横屏分别验证片库筛选、详情与播放器。

## 11. 不在本次范围

- 不抓取或展示豆瓣用户评论、影评全文、用户账号数据。
- 不登录豆瓣，不处理个人“想看/看过”数据。
- 不为本次九个来源之外的非 MacCMS 网站开发未知的专用适配器。
- 不把设备播放历史、测速明细或用户行为上传云端。
- 不重做现有影视页面的整体视觉风格。
