# 足球直播、影视播放器与更新链路快闪改造设计

## 1. 目标

一次性修复足球页今日比赛排布与刷新、重要赛事筛选、直播选源和切源体验；重新设计影视播放器选集与线路区域并缩小快进快退步长；完善启动资源门闸和更新链路，使后端及 Web 前端继续静默更新，同时让原生 Android UI 变更可通过完整 APK 分发。

## 2. 已确认规则

- 今日比赛优先填满第一行，每页最多四列、两行；向右移动时两行作为一页整体移动。
- 足球页处于前台时每 10 秒请求一次新数据，同时以设备时间在准确开赛点本地切为 `live`，不等待上游状态刷新。
- 用户手动选择某个足球直播源后，后续比赛优先使用同一 `src`；该场不存在或解析失败时按现有稳定顺序回退。
- App 必须等热更新检查、内置后端健康检查、关键资源校验及至少一份可用目录数据完成后再展示主页。所有等待必须有超时降级，不能造成永久启动阻塞。
- “重要”只匹配热门球队白名单，不再根据中超或“五大联赛”赛事名称整体纳入。中超仍保留独立筛选。
- 切换直播源时立即停止旧会话、冻结或清除旧画面、展示切换状态；新源预解析成功后开始播放。旧会话的迟到回调不能覆盖新源。
- 少于 20 集只显示二级数字集数；20 集及以上显示一级分段 `第1-10集`、`第11-20集`，二级显示 `1`、`2`、`3`。
- 影视播放线路只展示探活成功、`available=true` 的综合排名前五条，对用户重命名为“信号源1”到“信号源5”，内部仍保留稳定线路 ID。
- 影视点播快进和快退步长统一为 10 秒；直播不启用点播式快进快退。
- Python 后端和 `www/` Web 前端沿用无感更新：不显示 App 内弹窗，校验完成后自动替换并重启内置后端。
- 原生 Compose UI 无法由 Python/Web 热更新包替换。涉及原生 UI 时发布完整 APK；App 不显示二次确认弹窗，下载校验后直接拉起 Android 系统安装界面。非系统签名、非 Device Owner、非 Root 设备仍需用户完成系统安装确认。
- 本次只构建和验证，不自动部署或推送线上版本。

## 3. 足球列表与实时状态

### 3.1 今日比赛双行整页横滑

今日比赛使用一个横向分页容器。每个分页项内部是四列两行网格：数据按先行后列分配，前四场进入第一行，第五至第八场进入第二行。因此截图中的五场比赛会显示为第一行四场、第二行一场。遥控器左右键跨过页边界时切换整个八场页面，两行同步移动；上下键只在当前页两行间移动。明日及以后保持现有纵向分组布局。

### 3.2 即时状态

后端缩短比赛列表的活动时段缓存，并在每次返回前重新用计划开赛时间归一化状态。Android 足球页每 10 秒执行一次去重静默刷新。页面还为最近一个未开赛项目设置本地定时器，到达开赛时间时立即将该项目投影成 `live` 并触发后台刷新。上游明确完场或已超过合理比赛时长时不强行标记直播。

### 3.3 重要赛事

建立规范化热门球队白名单，覆盖项目当前重点展示的欧洲豪门、国际米兰等热门队名及常见中文别名。`important` 筛选与 Hero 重要性均依据主客队是否命中白名单；直播中和有比分只影响命中后的排序，不扩大成员范围。中超和足协杯不自动进入重要，仍可通过“中超”标签查看。

## 4. 足球播放会话

`SettingsStore` 继续保存最后一次由用户主动选择的 `src`。进入下一场比赛时，先从该场动态线路表中查找同一 `src`，找到后优先解析；不存在或失败才回退到 `bb`、`plu`、动态高清源顺序。自动故障换线不会覆盖用户偏好。

切源采用递增会话代数：点击后立刻暂停并清空旧媒体项、进入“正在切换信号源”状态，再解析或使用预解析缓存启动新源。所有解析和播放器回调携带会话代数，只有最新代可以写入 UI 或播放引擎，解决旧源画面延迟残留和迟到结果倒灌。

## 5. 影视播放器侧栏

选集区拆成清晰的两级视觉层：一级分段使用较深容器、较大圆角和完整文字；二级数字使用紧凑网格，选中态采用高对比主色填充，焦点态增加描边和轻微缩放。少于 20 集时一级区域完全不占空间。

线路数据进入播放器前先过滤 `available=false`，按后端综合得分保序截取前五条。显示标签仅使用“信号源N”，详情、播放和失败切换继续使用内部 `lineId`。若五条均不可用，保持“暂无可用信号源”错误态，不展示死线路。

点播遥控器左右快进快退由当前较大步长调整为每次 10 秒，并保留 0 与视频时长边界限制。

## 6. 启动与更新

启动页聚合四项就绪条件：热更新元数据检查完成、内置后端健康、打包资源清单完整、影视目录恢复快照或实时刷新成功。各条件保留独立错误信息和总超时；超时后若已有本地有效资源则降级进入，无有效资源则显示可重试错误页。

后端/Web 无感包必须包含并校验 Python 模块、`www/index.html`、`www/app.js`、`www/style.css`、静态资源和内容散列。下载成功后按散列而非仅按文件大小决定重新解压，原子替换运行目录并重启 `:backend`；健康检查通过后才记录“已更新”。WebView/浏览器入口追加版本参数或禁用旧入口缓存，保证新 Web UI 被加载。

原生 UI 发布使用同一管理入口生成 APK 更新记录。App 检测到 APK 版本时静默下载并校验签名与 SHA-256，不显示自定义确认弹窗，随后直接打开系统安装器。系统不允许普通应用静默安装自身，因此系统确认界面是不可消除的安全边界。

## 7. 测试与验收

- 单元测试验证五场今日比赛分配为 `4+1`、九场分配为 `4+4` 后再开新页，并验证整页滚动模型。
- 使用固定时钟测试开赛点状态切换、完场保护、10 秒刷新去重。
- 测试中超不属于重要、热门球队属于重要、别名能命中。
- 测试用户主动选择源被记住、下一场优先、缺源回退、自动换线不覆盖偏好。
- 测试切源后旧会话回调被丢弃且旧媒体立即停止。
- Compose/JVM 测试验证 19 集无一级菜单、20 集产生两个分段、线路只留可用前五条、标签为“信号源N”、快进退为 10 秒。
- 测试启动门闸正常、缓存降级和无资源失败三条路径。
- 测试 Web 热更新内容散列变化会重新解压，校验失败不记成功；APK 更新签名/SHA 校验和系统安装 Intent。
- 完成后运行后端全量测试、JavaScript/Python 语法检查、TV 与移动端单元测试和 Debug 构建；必要时在 Android 模拟器执行足球页、切源和影视侧栏实机流程。

## 8. 非目标

- 不尝试绕过 Android 系统安装授权。
- 不引入服务端集中豆瓣目录。
- 不改变足球源站或新增第三方足球直播来源。
- 不在本次工作中部署云函数、发布热更新或推送 APK。

## 9. 追加需求：网页播放器控制栏

网页版影视播放器增加统一控制栏：返回、播放/暂停、可拖动进度条、当前时间与总时长、全屏、更多（三点）按钮。控制栏在鼠标、触屏或键盘操作时出现，播放数秒后自动淡出；暂停、拖动和更多菜单展开时保持可见。更多菜单承载播放速度、信号源和选集入口，不重复堆叠主操作。直播内容隐藏不可用的点播进度与倍速。所有按钮提供可访问名称、键盘焦点和触屏热区。

## 10. 追加需求：足球队标提供方

`football-logos.cc` 提供透明 PNG/SVG 与多分辨率资源，技术上适合构建期同步；但其公开限制只允许信息、编辑、非商业设计和球迷项目，并禁止商业产品使用，源码仓库也未提供可覆盖该限制的开源许可证。当前项目包含付费卡密，因此本次不得打包、热链或分发该站队标。

队标读取改成提供方无关的混合结构：内置资产优先、合法在线来源补缺、成功结果落本地缓存、失败回退文字首字母。先保留现有合法来源和现有内置队标；未来获得书面授权或更换为明确允许商业使用的来源时，只需替换构建期清单与在线 URL 解析器，无需改 UI。
