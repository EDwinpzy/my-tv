# 豆瓣本地搜索、播放自愈与生命周期统一设计

## 目标

在不改变现有影视展示结构和播放源体系的前提下，将豆瓣刮削结果持久化为设备本地媒体库，统一 TV、移动端和 Web 搜索；同时修复足球直播及影视点播长时间播放后的失效、卡顿、恢复和退出生命周期问题，并完成三端发布。

## 数据与搜索

- 豆瓣仅负责影片元数据。首页、片库、详情的成功响应都会增量写入 SQLite。
- 数据库固定保存到 App 私有持久目录 `filesDir/media/mytv.db`，不得放进会被热更新覆盖的 `embedded_backend`。
- 数据库采用版本化迁移，已有数据与搜索索引在 APK 和后端热更新后继续保留。
- 搜索请求只查询 SQLite，不在搜索过程中访问豆瓣或播放站。
- 搜索覆盖标题、别名、原名、演员、导演、类型、全拼和拼音首字母；支持季数合并输入、包含匹配以及结果不足时的轻量容错。
- `/api/search?q=&limit=` 是三端唯一搜索入口；结果使用现有豆瓣卡片结构，进入详情后再匹配项目内受管播放源。

## 播放自愈

- 后端直播成功地址最多缓存 60 秒；未开播、解析异常和无播放器地址不进入五分钟正缓存。
- Android 监控 `BUFFERING`、播放位置和缓冲进展。直播连续 8 秒无进展后依次执行同地址重载、`fresh=1` 同源解析、换源、重建引擎、重置解密池/后端；所有动作有次数预算。
- 点播恢复保存集数和位置，重新解析同线路后从原位置前 1–3 秒继续；失败后才切换综合排序的下一线路。
- 恢复和切源使用递增会话代数，旧播放器或旧网络请求的迟到回调不得覆盖当前会话。
- Web 使用同等的有限恢复阶梯；HLS 致命错误不得只对过期 URL 重复 `startLoad()`。

## 刷新与生命周期

- 足球页可见时约每 10 秒静默刷新，并继续用本地时钟在开赛点立即投影为 `live`。
- 页面重新可见、Activity 回前台、网络恢复、Web `focus/pageshow/online` 时触发一次去重刷新。
- 普通后台不等于退出；直播后台超过 30 秒后返回必须重新解析地址。
- 用户双击返回明确退出时，依次停止刷新任务、播放器、解密 WebView 池、8091 服务和 `:backend` 服务进程，再结束任务。
- `BackendService` 使用 `START_NOT_STICKY`；热更新和播放故障需要后端时由主进程显式拉起。

## 更新与发布

- Python、SQLite 搜索模块和 Web 前端进入同一个后端热更新包，包内不得包含设备数据库。
- Kotlin 改动同步到 TV 和移动端并发布新 APK。
- 本次用户已明确授权：部署公网 Web、推送 App 热更新、构建并发布两端 APK、提交并推送 Git。

## 验收

- 本地搜索覆盖中文、别名、全拼、首字母、季数、演员及容错样例；断网时仍可搜索已刮削内容。
- 直播地址缓存和负缓存行为有自动化回归测试。
- Android 恢复状态机、退出策略和前后台决策有 JVM 测试。
- Web 契约测试覆盖本地搜索、可见性刷新和 HLS 新地址恢复。
- Python 全量测试、TV/移动单测与 APK 构建、浏览器实测、模拟器截图和日志验证全部通过后才发布。
