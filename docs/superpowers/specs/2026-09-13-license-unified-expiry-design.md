# 卡密统一有效期与 24 小时复验宽限设计

**日期：** 2026-09-13  
**状态：** 已确认  
**输入需求：** `C:\Users\63054\Desktop\卡密系统调整说明.md`

## 1. 目标

将卡密有效期从“每台客户端本地计算”改为“服务端为每张主卡保存唯一有效期”。同一张卡绑定的两台设备共享 `activated_at` 和 `expire_at`；设备身份只看哈希后的 `deviceId`；联网失败最多宽限 24 小时，明确的封禁、过期、解绑或无效卡立即失效。

本次同步覆盖 TV、移动版、网页版、激活云函数、PostgreSQL RPC、后台管理、构建产物和项目文档。现有卡密与激活日志全部清空，按清空前各套餐数量重新生成等量新卡。

## 2. 不变项

- 卡密格式仍为 `OTV-XXXXX-XXXXX`。
- 套餐仍为 weekly、monthly、quarterly、yearly、lifetime。
- 票据仍使用 ECDSA P-256 + SHA-256，私钥只保存在本机。
- 一张主卡最多绑定 2 个 `deviceId`。
- 同卡同设备重复激活幂等。
- 后台继续支持封禁、解封、单台解绑和全部解绑。
- 续费公式仍为 `max(当前 expire_at, now) + days`。

## 3. 数据模型

`licenses` 新增：

| 字段 | 类型 | 含义 |
|---|---|---|
| `activated_at` | `timestamptz null` | 主卡首次激活时间；空值表示从未激活 |
| `expire_at` | `timestamptz null` | 主卡统一到期时间；已激活且为空表示终身 |
| `redeemed_at` | `timestamptz null` | 续费卡被兑换的时间 |
| `redeemed_to` | `text null` | 续费卡延长的主卡卡号 |

`devices` 继续保存 JSONB 数组，只保存最终 SHA-256 字符串。`max_dev` 保持 2。

续费时旧卡继续作为主卡，新卡只作为一次性续费凭证：锁定两行，延长主卡 `expire_at`，在续费卡写入 `redeemed_at/redeemed_to`。两台设备继续持有原主卡，无需再次输入续费卡。

若主卡已是 lifetime，拒绝继续消耗续费卡。lifetime 续费卡兑换到普通主卡时，将主卡 `expire_at` 设为空。

## 4. 授权协议 v2

所有新客户端请求增加 `protocol: 2` 和 `action`：

- `action: "activate"`：显式激活，可在未满 2 台时新增当前设备。
- `action: "verify"`：启动、回到前台或使用会员能力时复验，只检查设备，不新增绑定。
- `action: "renew"`：提交新续费卡，同时发送 `currentCode`；服务端延长当前主卡。

成功响应：

```json
{
  "ret": 0,
  "ticket": {},
  "licenseCode": "OTV-AAAAA-BBBBB",
  "activatedAt": "2026-09-13T10:00:00Z",
  "expireAt": "2026-10-13T10:00:00Z",
  "serverNow": "2026-09-13T10:00:01Z"
}
```

终身卡的 `expireAt` 为 `null`。`ticket` 始终是主卡的预签名票据；客户端先验签票据，再接受 HTTPS 响应中的服务端有效期。

返回码：

| ret | 含义 | 客户端行为 |
|---:|---|---|
| 0 | 成功 | 保存服务端统一时间和最后成功复验时间 |
| 400 | 参数或卡密格式错误 | 显示输入错误 |
| 402 | 设备数量已满 | 保留本地旧会员状态 |
| 403 | 卡密封禁 | 立即清除本地会员 |
| 404 | 卡密不存在 | 复验时立即清除；显式输入时提示不存在 |
| 405 | 已过期 | 立即停止会员能力，允许输入续费卡 |
| 406 | 当前设备未绑定 | 立即清除本地会员 |
| 409 | 续费卡已兑换 | 提示不可重复使用 |
| 410 | 主卡已是终身 | 不消耗续费卡并提示无需续费 |
| 426 | 客户端授权协议过旧 | 提示升级 App |
| 5xx/网络错误 | 服务暂不可用 | 进入 24 小时宽限逻辑 |

旧客户端未发送 `protocol: 2` 时返回 426，防止新卡继续被旧版按本地激活时间计算。

## 5. 首次激活、复验和续费事务

### 首次激活

1. `SELECT ... FOR UPDATE` 锁定卡记录。
2. 检查存在、未封禁、未兑换。
3. 若 `activated_at` 为空，将其设为数据库 `now()`；普通卡设置 `expire_at = activated_at + days`，终身卡设置为空。
4. 当前设备已存在则幂等通过；否则在设备数小于 2 时追加，满 2 台返回 402。
5. 返回主卡票据和统一时间字段，写入激活日志。

### 联网复验

1. 锁定或读取主卡，不修改 `devices`。
2. 检查卡存在、未封禁、未过期且当前 `deviceId` 已绑定。
3. 返回主卡票据与统一时间；失败返回明确业务码。

### 续费

1. 按固定卡号顺序锁定主卡和续费卡，避免死锁。
2. 验证当前设备属于主卡；主卡可处于已过期状态，但不能被封禁。
3. 验证续费卡从未激活、未绑定、未兑换且未封禁。
4. 普通续费卡执行 `max(主卡 expire_at, now()) + days`；lifetime 续费卡把主卡改为终身。
5. 标记续费卡 `redeemed_at/redeemed_to`，返回主卡票据和新有效期。

## 6. 设备标识

Android 使用完整 64 位十六进制 SHA-256：

```text
SHA256(ANDROID_ID + "|" + packageName + "|" + Build.MODEL)
```

不再加入 `Build.MANUFACTURER`，不再截断哈希。TV 与移动版包名不同，因此同一物理设备安装两个 App 时会占两个独立设备名额，这是协议明确行为。

网页版生成并持久化随机安装种子，再计算 `SHA256(seed + "|web|" + location.origin)`；请求、数据库和日志只出现最终哈希。

## 7. 客户端 24 小时宽限

客户端保存服务端返回的统一有效期和 `last_verify_success_at`，删除本地最大时间戳账本、48 小时回拨冻结及 HTTP Date 校准。

- 明确返回 403、404、405、406：立即失效。
- 网络错误或 5xx：最后成功复验后 24 小时内继续放行。
- 连续超过 24 小时无法成功复验：暂停会员能力并提示联网验证。
- 网络恢复且复验成功：自动恢复，不要求重新输入卡密。
- 首次使用新协议但没有成功复验时间：必须联网成功后才放行。

TV/移动版在启动、进程回到前台及会员入口触发节流复验；长时间前台运行时按短周期重试。网页版启动、恢复可见和播放门控前执行同样的节流复验。

## 8. 后台管理

卡密列表增加首次激活时间、统一到期时间和续费兑换状态。筛选继续保留未售、已售、已激活、已封禁，并增加已兑换状态。详情仍展示设备哈希并支持单台/全部解绑。

后台不生成签名票据；新卡仍在本机通过 `license_gen.py` 生成并导入。

## 9. 存量清理与重新生成

这是一次显式授权的破坏性迁移，执行顺序固定：

1. 在本机导出旧卡按套餐数量统计和必要审计备份。
2. 部署协议 v2 数据库函数与服务端代码。
3. 清空 `activate_log` 和 `licenses`。
4. 按清空前 weekly/monthly/quarterly/yearly/lifetime 数量生成等量新卡。
5. 导入新卡，确认全部未售、未绑定、未激活。
6. 发布新版 TV、移动 APK 和网页版；旧版激活请求由协议门槛拒绝。

重置操作单独放在一次性脚本中，不嵌入可重复执行的结构迁移，避免以后重跑迁移时误删新卡。

## 11. 部署与回滚

先部署兼容新字段的数据库与服务端，再发布客户端。正式清空旧卡前保存本机统计和备份；清空后旧卡不可再用。

代码回滚不能恢复已删除卡密。若协议 v2 发布失败，暂停发放新卡，回滚客户端/函数代码并从本机备份恢复数据库；恢复动作必须人工确认目标环境和备份文件。
