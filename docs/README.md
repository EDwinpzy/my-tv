# My TV 文档中心

这里是 My TV 的文档总入口。文档按用途分层，避免把当前规范、操作步骤、历史证据和临时讨论混在一起。

## 推荐阅读路径

1. [根目录 README](../README.md)：项目简介、目录结构和快速上手。
2. [项目文档](01-overview/项目文档.md)：当前架构、模块边界、数据来源和运行限制。
3. [开发与发布手册](02-guides/开发与发布手册.md)：开发、测试、构建、热更新和云函数发布。
4. [测试记录](04-records/测试记录.md)：自动化、模拟器、浏览器和线上验证证据。
5. [版本史](04-records/版本史.md)：按版本追加的功能变更摘要。

## 目录结构

| 目录 | 内容 | 维护规则 |
|---|---|---|
| [`01-overview/`](01-overview/) | 项目现状与架构 | 功能边界变化时更新，描述“现在是什么” |
| [`02-guides/`](02-guides/) | 开发、发布和云端操作指南 | 命令或流程变化时更新 |
| [`04-records/`](04-records/) | 版本史和测试记录 | 只追加，不改写历史结论 |
| [`superpowers/specs/`](superpowers/specs/) | 已确认的功能设计 | 需求确认后保存，设计冻结后不写流水账 |
| [`superpowers/plans/`](superpowers/plans/) | 分任务实施计划 | 实施完成后保留，便于追溯 |
| [`assets/`](assets/) | 文档截图和展示素材 | 文件名注明用途或版本 |

## 当前发布边界

- 本机是代码整理、构建、测试和 Git 发布的唯一入口。
- App 运行时可以通过公网获取豆瓣内容、播放源、热更新包和必要接口；公网是运行依赖，不是代码来源。
- Python 后端与 `www/` 静态资源可以热更新；Kotlin/Compose、播放器引擎和权限等原生改动必须重新构建 APK。
- Android TV 与移动版共享层使用 `tools/sync_shared.py` 检查；后端 zip 使用 `tools/build_backend_zip.py` 生成。

## 文档维护规则

- 现状文档写“现在是什么”；指南写“怎么操作”；版本史写“什么时候改了什么”；测试记录写“用什么证据验证了什么”。
- 命令注明工作目录和 Windows/Linux 差异；仓库内路径统一使用相对路径。
- 新需求先放入 `superpowers/specs/`，确认后再放入 `superpowers/plans/`；完成后把摘要追加到版本史和测试记录。
- 不在文档中保存私钥、卡密 CSV、服务密钥、完整 Cookie 或长期令牌。
